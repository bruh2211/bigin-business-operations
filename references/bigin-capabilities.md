## 📌 Critical Architectural Conclusions

1. **The Pipeline Definition Gap**:
   - Zoho Bigin's REST API exposes rich endpoints for reading layouts and managing pipeline *records* (deals, tickets, contacts), but **no public API exists to provision new Team Pipelines or create custom stage sequences**.
   - Therefore, browser automation (Playwright / Browser Use) is an **indispensable core component**, not a fallback.
2. **Zoho People Integration Truth**:
   - There is **no direct native toggle** in Bigin settings for Zoho People. Integration must be executed via **Zoho Flow** or an external webhook/API sync worker.
3. **Financial Invariant Verification**:
   - Invoices generated in Zoho Books are created in `draft` or `sent` status. Under no circumstance may an agent report a deal as "Paid" or issue a receipt until a verified `customerpayment` entity with matching amount and cleared status is returned by Zoho Books.
